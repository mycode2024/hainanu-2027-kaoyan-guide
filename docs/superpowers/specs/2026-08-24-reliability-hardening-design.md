# 海南大学 2027 考研导航：时效可靠性加固设计

## 目标

本轮不追求更高频地请求官网，而是保证每一次“数据新鲜”的结论都可信：相关公告不因关键词窄而静默漏掉，单个来源长期失败不会被其他来源的成功掩盖，官网结构异常不会覆盖完整缓存，标题修改不会伪装成新公告。

## 边界与兼容性

- 保持零第三方运行时依赖，只使用 Node.js 内置模块与 PowerShell 5.1+。
- 服务仍只监听 `127.0.0.1`，只访问配置中的 HTTPS 官方域名。
- 保持 `/api/updates`、`/api/refresh` 和 `/api/health` 路径兼容；数据契约继续使用 `schemaVersion: 2`，新增字段均可选。
- 每小时自动刷新不变。来源失败时优先展示可信旧缓存，不以提高请求频率掩盖质量问题。
- 静态文件模式和现有待办数据继续可用。

## 抓取与公告身份

每个来源使用宽召回、明确排除的规则。海南大学来源接受“研考、考点、考生、网上确认、报名、初试、复试、调剂、拟录取”等组合；研招网接受“硕士研究生招生”中插入“计划、考试、工作”等修饰词的正式政策标题，同时排除仅博士、本科和培养管理内容。

解析器从包含日期与官方链接的列表或公告块提取候选项，输出解析诊断：候选数、相关记录数和发现的容器类型。稳定公告 ID 由 `sourceId + 规范化 URL` 生成；标题及分类生成独立 `contentHash`。同一 URL 标题改变时保留 `discoveredAt`，记录 `updatedAt` 和 `changeType: "updated"`。

海南大学首页的短日期按 `Asia/Shanghai` 日历推断年份，并验证日期真实存在，避免 UTC 跨月/跨年误判。

## 结构漂移与历史保护

来源成功不再只依赖“至少解析到一条”。当已有足够历史样本时，以下任一条件将结果标记为 `degraded` 并保留该来源旧缓存：

- 本次记录数低于上次可见记录数的 40%，且上次至少有 5 条；
- 旧 URL 消失超过 70%，且没有足以解释换页的新记录；
- 最新发布日期相对缓存倒退超过 120 天。

正常成功刷新也不会立刻删除官网当前列表中消失的项目。缺失项记录 `missingSince` 和 `missCount`，最多保留 90 天或 168 次连续缺失；重新出现时清除缺失标记。全局容量分配按来源保底并优先保留本轮新发现项目，避免大量带“2027”的旧项挤掉新报名通知。

## 新鲜度与可观测性

快照新增：

- `lastAttemptAt`：最近一次刷新尝试；
- `lastAnySuccessAt`：最近任意来源成功；
- `lastAllSuccessAt`：最近全部必要来源成功；
- `freshness.overdueSourceIds`、`freshness.worstSourceAgeMs`；
- 每个来源的 `freshness`、`ageMs`、`isOverdue`、`degraded`。

总体新鲜度由最差的必要来源决定：任何来源从未成功为 `never`，超过两个刷新周期为 `overdue`，超过一个周期为 `aging`。页面明确显示“部分来源已逾期”，不再用全局最近成功时间掩盖它。

每次刷新记录结构化摘要，包括耗时、每来源尝试次数、解析数量、降级原因、新增和更新数量、缓存是否写入。健康接口暴露运行时长、最近尝试、最近全量成功和逾期来源。

## 重试与缓存恢复

- HTTP 200 但零结果或结构诊断异常允许再尝试一次。
- HTTP 429 读取并限制 `Retry-After`，所有重试等待均有上限并加入轻量抖动。
- 写缓存前保留一个 `.bak`；主缓存损坏时加载备份并在快照中显示恢复警告；主备都不可用时明确报告缓存损坏，而不是伪装成第一次启动。

## 前端与 Windows 生命周期

- 时间线支持多个并行活跃节点，并在预计日期旁明确显示“预计”；静态 fallback 不使用永久的“进行中”。
- 自动更新改为请求完成后安排下一次轮询，页面隐藏时暂停，使用超时和单飞锁；只有数据版本发生变化才重绘公告列表，避免键盘焦点丢失。
- 新公告按“本次访问基线”保持可见，并提供“全部/只看新”与明确的确认已读动作；存储不可用时显示“仅本次会话保存”。
- 打印输出保留待办标签及勾选状态，并打印数据核验时间。
- 启动器使用命名互斥锁，统一 `-Port` 与子进程 `PORT`，原子写 PID；停止器区分查询失败和进程不存在，等待进程退出并确认端口服务消失后才删除 PID。
- 日志按数量保留最近 14 组，并让浏览器打开失败仅作为警告，不把已启动服务误报为失败。

## 验收标准

1. 两个已确认漏抓的真实标题进入解析回归测试并通过。
2. 标题改变保持同一 ID，产生更新事件而非新增事件。
3. 结构骤降、日期倒退和大比例 URL 消失不会覆盖来源缓存。
4. 单个来源逾期会使总体状态显示部分逾期，并列出该来源。
5. 正常列表收缩保留有界历史，新发现项目不会被容量排序丢弃。
6. 零结果会重试，429 尊重有上限的 `Retry-After`。
7. 损坏主缓存能从备份恢复并显示警告。
8. 前端多个并行节点、非重叠轮询、未读确认、存储降级和打印状态均有可验证行为。
9. Windows 重复启动只产生一个项目进程，停止后进程与健康端点都不可访问。
10. 完整自动化检查、真实四来源刷新、健康接口和本地页面请求全部通过。
